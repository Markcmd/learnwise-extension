# 2026-06-28 — M2.4: decks + manual capture

## Goal
Let users group words into decks and manually capture words they highlight on a
page (not just words auto-promoted by reading).

## What shipped
- **`core/decks.js`** — pure deck CRUD + word membership + `getDecks`/`setDecks`.
- **Manual capture** — `dom/selectionAction.js` generalized to `resolveAction`;
  `contentScript.js` `captureWordIO` (save highlighted word → bank + review).
- **Settings** — Decks card (add/rename/delete + counts) and per-word deck
  chips; inline deck mirror in `settingsWindow.js`; styles in `settings.css`.
- **Tests** — `tests/decks.test.js`. Manifest → 1.0.6.

## Decisions
- **Membership lives on the word (`Word.tags`), not on the deck.** Matches the
  DESIGN ER model (WORD }o--o{ DECK), makes rename/delete O(1) on the deck, and
  supports a word being in several decks. `deckCounts`/`wordsInDeck` derive
  membership by scanning tags.
- **Decks de-dupe by case-insensitive name** to stop "Work"/"work" doubles;
  `createDeck` returns the existing deck instead of erroring.
- **selectionAction went from two fixed callbacks to one `resolveAction`.** The
  floating button is now fully data-driven (label + run), which is what let us
  add "Save word" without a second button. The content script decides per word:
  known → Review again; untracked → Save word; already-learning → nothing
  (it's already glossed + clickable, so no selection action needed).
- **Manual capture seeds the word due *now*** (same call as the review queue),
  so a highlighted word is immediately reviewable, and inserts it at a glossing
  level so it also gets annotated on the page.
- **Settings duplicates deck logic** because it's the unbundled classic script
  (same pattern as popup/providers). Flagged as keep-in-sync.
- **Deck assignment UI = chips in the word detail**, rather than a separate
  assignment screen — reuses the existing expandable word list, low friction.

## Verification

## REVISION (same day) — decks pivoted to AUTOMATIC (difficulty)
User feedback: *"Deck feature — users never operate on this. Consider another
method."* → manual decks were the wrong model. Chosen replacement:
**automatic decks grouped by difficulty** (word frequency rank).

What changed from the first cut:
- **Removed** `core/decks.js`, `tests/decks.test.js`, `STORAGE_KEYS.DECKS`, and
  all manual deck CRUD + per-word chips from settings. (Recoverable via git if
  manual decks ever return for a power-user mode.)
- **Added** `core/difficulty.js` (pure, tested): bands from frequency rank —
  Beginner 1–600 / Intermediate 601–1200 / Advanced 1201+ / Rare = unlisted.
- **Added** `data/frequency.json` — web-accessible mirror of
  `JSs/data/frequencyWords.js`, fetched by the unbundled settings page to build
  the rank index. JS module remains source of truth (regenerate JSON on edit).
- **Settings** Decks card now shows four auto difficulty groups (counts +
  expandable lists); word detail shows a read-only Difficulty row.
- **Kept** the manual-capture work (selectionAction `resolveAction` + "Save
  word") — it's independent of how decks are organized and still useful.

Why derive instead of store a tag: difficulty is a deterministic function of the
static frequency list, so deriving keeps it always-correct with zero curation
and zero migration — exactly the "store facts, derive scores" principle, and it
satisfies "users never operate on decks." Verified: **24 assertions pass**
(difficulty logic + frequency.json parity). Manifest → 1.0.7.
