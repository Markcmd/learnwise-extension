# 2026-06-29 — M4.1: Privacy policy (launch prep)

First task of **M4 — Launch**. Scope this session: **privacy policy only**
(4.1), hosting decided as **GitHub Pages**. (In-app note + 4.2/4.3/4.4 deferred.)

## What I did

- Wrote the privacy policy, grounded in the **actual** data flow (verified
  against the code, not assumed):
  - **All storage is local** — `chrome.storage.local` + IndexedDB. No server
    (EC2 is shut down), no analytics/telemetry (grep confirmed the only `fetch`
    in `JSs/` is the BYOK provider call in `dom/llm.js` plus local
    ECDICT/`frequency.json` loads).
  - **Domain-only logging by default**; full-URL is opt-in. Confirmed:
    `contentScript.js` reads `STORAGE_KEYS.LOG_FULL_URL` and only logs the full
    URL when it's `=== true`, so the default is domain-only.
  - **Retention:** `EVENT_RETENTION_DAYS = 90` — policy says "roughly 90 days,
    collapsed into per-word aggregates," matching `core/pruning.js`.
  - **BYOK smart translation** is the *only* thing that leaves the device, and
    only when the user opts in with their own key. Verified what's sent:
    `core/translation.js` `buildUserContent` sends the **word(s)** + an optional
    **single context sentence** to the user-chosen provider
    (OpenAI/Anthropic/OpenRouter/custom). Key is read only in the background
    worker, never on the page. Request goes browser→provider directly, no
    LearnWise server.
  - **Permissions justified** to match `manifest.json`: `<all_urls>` content
    script, `storage`/`unlimitedStorage`, provider `host_permissions`
    (`api.openai.com`, `api.anthropic.com`, `openrouter.ai`), custom endpoint via
    `optional_host_permissions` requested at setup.
