# 2026-06-29 — M3.2: charts + dashboard page (M3 COMPLETE)

## Goal
A dedicated progress dashboard that turns the M3.1 stats into a visual page —
headline numbers, familiarity distribution, a streak, review accuracy, and a
30-day activity chart.

## What shipped
- **New page** `HTMLs/dashboard.html` + `CSSs/dashboard.css` + `JSs/dashboard.js`
  (**bundled** → `dist/dashboard.js`; added to `build.mjs` entryPoints). Like the
  review page it's an extension-origin page, so it reads `chrome.storage.local`
  and the extension's IndexedDB **directly** (no background hop): loads the bank
  + full exposure/review logs, hands them to `computeStats()` (M3.1), and renders.
- **Charts (hand-rolled SVG/CSS, zero runtime deps — house style):**
  - Six headline cards: words tracked, known, added this week, **day streak**
    (with 🔥 + longest/active-days subline), reviews done, review accuracy.
  - **Familiarity** distribution — horizontal bars per tier (new/learning/
    familiar/known), coloured on a low→high ramp.
  - **Review accuracy** — an SVG donut (filled arc = accuracy) + a grade
    breakdown (Again/Hard/Good/Easy bars in the review palette).
  - **Activity** — a full-width 30-day SVG sparkline; each day stacks reading
    (blue) under reviews (green), with a hover `<title>`, date axis, and summary.
  - Loading + empty states; **live refresh** on `chrome.storage` wordbank
    changes and a manual Refresh button.
- **`core/events.js`**: added flat full-log readers `getAllExposures()` /
  `getAllReviews()` (the dashboard needs whole logs; the existing reads were
  grouped/by-word/by-index only).
- **Popup:** the old button labelled "Open Dashboard" actually opened *Settings*
  — relabelled to **Settings**, and added a real **Progress dashboard** button
  (→ `dashboard.html`). `popup.js` wires `openDashboard`.
- Manifest → **1.0.10**.

## Decisions
- **Local-day bucketing in the UI.** `computeStats` is called with
  `tzOffsetMin = -new Date().getTimezoneOffset()` so "today"/streaks line up with
  the user's calendar day, while the pure logic stays UTC-deterministic for tests.
- **Reuse, don't re-mirror.** The page imports `FAMILIARITY_TIERS`/`STATS` and
  `computeStats` directly (it's bundled), so — unlike the unbundled settings/popup
  scripts — there's **no inlined mirror to keep in sync**.
- **SVG over a chart lib.** Stays consistent with the rest of the project (no
  runtime deps), keeps the bundle tiny, and the charts are simple enough.
- **Distinct from Settings.** Settings keeps its small stat cards + level chart
  (D-002/003) as an at-a-glance strip; the dashboard is the richer, dedicated
  view. Both now reachable from the popup.

## Verification

  `manifest.json` parses (v1.0.10).

  strip; do a review and confirm accuracy + activity update.
