# Session log — 2026-06-28 — "n/a" gloss words

Full narrative of the session: the concern, what we found, what we proposed,
how we decided, and the conclusion. Companion reference docs:
[../problems/na-words.md](../problems/na-words.md) and
[../decisions/na-words.md](../decisions/na-words.md).

---

## 1. The concern (where it started)

Mark: *"Let's deal with n/a words, which are not in the local dict."*

When LearnWise wants to gloss a word but has no translation for it, the ruby
annotation shows the literal text **`n/a`** above the word. That's noise, and it
flags words we can't actually help with.

## 2. The problem, diagnosed

Traced the path through the code:

- `JSs/dom/scanner.js` tokenizes **every** `[A-Za-z]+` token in the viewport.
- `JSs/core/wordbank.js` → `splitWords()` puts any token **not in the word
  bank** into the `show` + `unknown` sets — i.e. we try to gloss it.
- `JSs/dom/ecdict.js` → `fetchTranslationFromLocalDictionary()` returns
  `{ meaning: "" }` when the word isn't in the bundled ECDICT shards.
- `JSs/dom/renderer.js:109` — `pickFirstChineseTranslation(...) || "n/a"`.
  Empty meaning ⇒ the placeholder **`n/a`** is rendered.

So `n/a` = "this token was treated as glossable but has no local entry."

Key empirical findings (measured against the shipped `ecdict_json/`):

- ECDICT has **~404k entries**.
- **All** curated frequency words and common words are already present (0 missing).
- **All** common contractions (don't, we'll, it's, …) are present.
- Only a small set of **modern/neologism words** were genuinely missing
  (chatbot, metaverse, ransomware, deepfake, doomscrolling, …).

Implication: most `n/a` on real pages is **proper nouns / brands / typos**, not
real vocabulary. Those can't be fixed by growing the dictionary.

## 3. What we proposed

Two separate problems emerged; we kept them apart:

**(A) Offline coverage** — reduce `n/a` for *real* words with no API.
Options considered: skip the gloss / subtle marker / styled `n/a` (all cosmetic,
rejected) → lemmatize-then-retry → **expand the local dict** (chosen).

**(B) Reader-side affordance** — what a *user* can do when they hit an `n/a`.
Options considered: on-demand AI lookup (BYOK) / type-your-own gloss / open
external dictionary / just dismiss (today's click-to-mark-known behavior).

## 4. What we decided

- **(A) Expand the local dictionary.** Built a supplement + merge pipeline and
  merged 43 confirmed-missing modern words. Done and verified.
- **(B) Leave it for now.** Conclusion reached together: to show a **real inline
  gloss** for an off-dictionary word you need either a bigger local dict or an
  online lookup (AI or a dict API). Without an API the only no-infra move is a
  click-to-open-external-dictionary escape hatch — a redirect, not an inline
  gloss. Type-your-own only helps if the reader already knows the word. So we
  chose **not** to build a reader-side feature now.
- The earlier offer to **gate glosses on dict-membership** (don't annotate
  tokens absent from the dict) was **not taken** — noted as a future option.

## 5. Conclusion / current state

- Shipped: `dict-supplement/supplement.json` (+43 words) and
  `tools/merge-supplement.mjs` (idempotent shard-merge, no npm deps).
- The dictionary shards in `ecdict_json/` now include those 43 words; lookups
  verified; re-running the merge adds 0 (idempotent).
- Dictionary expansion is the **only lever that improves the offline
  experience** and is independent of the shelved reader-side decision — so the
  work stands.
- Open/parked: reader-side `n/a` handling; dict-membership gating.

## 7. How to continue the dictionary work

1. Collect real words that show `n/a` while reading.
2. Add `{ "w": "...", "p": "...", "t": "中文释义" }` to
   `dict-supplement/supplement.json`.
3. `node tools/merge-supplement.mjs` (use `--dry-run` to preview).
4. Reload the extension — shards are web-accessible, **no `npm run build`** needed.
