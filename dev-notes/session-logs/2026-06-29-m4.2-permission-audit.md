# 2026-06-29 — M4.2: Permission audit (launch prep)

Second task of **M4 — Launch**. Goal: justify every permission, drop anything
unused, and prepare the store review-form text.

## Audit (manifest v1.0.11 → v1.0.12)

Checked each declared permission against actual code usage:

| Permission | Verdict | Evidence |
|---|---|---|
| `storage` | **Keep** | word bank / settings / logs in `chrome.storage.local`. |
| `unlimitedStorage` | **Keep** | vocab + event/review history can exceed default quota. |
| `activeTab` | **DROPPED** | unused. No `executeScript`, `scripting`, `captureVisibleTab`, `tab.url` read, or `action.onClicked` anywhere. The only `chrome.tabs.*` calls are `create`/`getCurrent`/`remove`, **none of which require a permission**, and the content script already has page access via `<all_urls>`. |
| host: `api.openai.com`, `api.anthropic.com`, `openrouter.ai` | **Keep** | BYOK smart-translation provider calls (`dom/llm.js`). Off by default. |
| optional host: `http://*/*`, `https://*/*` | **Keep** | requested at runtime only for a user-configured custom endpoint (`core/providers.js` builds the origin pattern; not granted at install → no install warning). |
| content script `<all_urls>` | **Keep** | core glossing must run on any page the user reads. |
| `web_accessible_resources` (`ecdict_json/*.json`, `data/frequency.json`) | **Keep** | content-side ECDICT shard fetch (`dom/ecdict.js`) + settings frequency list (`settingsWindow.js`). Not an install-warning permission. |

No `alarms`/`notifications`/`cookies`/`webRequest`/`contextMenus`/`scripting`
present — confirmed via grep, nothing to add or remove there.
