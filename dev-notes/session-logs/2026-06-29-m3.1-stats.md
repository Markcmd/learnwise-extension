# 2026-06-29 — M3.1: stats aggregation (test-first, pure)

## Goal
The data layer for the M3 progress dashboard: derive every dashboard number
from the bank + event logs. No new storage — "store facts, derive scores."

## What shipped
- **`core/stats.js`** (pure, no chrome/DOM/IndexedDB):
  - `dayIndex(ts, tzOffsetMin=0)` — integer day number (UTC by default for
    deterministic tests; pass `-new Date().getTimezoneOffset()` for local days).
  - `activeDays(events, reviews, tz)` — Set of days with ANY activity
    (exposure **or** review event).
  - `computeStreak(dayset, todayIndex)` → `{current, longest, activeDays,
    lastActiveDay}`. Current streak counts the consecutive run ending **today
    or yesterday** (one grace day); longest is the best run ever.
  - `levelDistribution(bank)` — familiarity-tier histogram, reuses
    `deriveStatus` so it can't drift from the glossing rule; excludes `ignored`.
  - `reviewAccuracy(reviews)` → `{total, correct, accuracy, byGrade}`; correct =
    SM-2 quality ≥ `STATS.CORRECT_QUALITY_MIN` (good/easy).
  - `activitySeries(events, reviews, {now, days, tz})` — dense, fixed-width
    per-day series ending today (every day present, even empty) for the
    sparkline/heatmap.
  - `wordsAddedSince(bank, now, windowDays)` — count by `createdAt`.
  - `computeStats(bank, events, reviews, opts)` — the single aggregate object
    the dashboard (M3.2) will consume: `{totals, distribution, streak, reviews,
    activity, generatedAt}`.
- **`core/constants.js`**: new `STATS` block (`ACTIVITY_DAYS 30`, `WEEK_DAYS 7`,
  `CORRECT_QUALITY_MIN 4`) — one place to tune dashboard windows.
- **Tests:** `tests/stats.test.js`.

## Decisions
- **Days are integer day-indices, not `Date` objects.** `Math.floor(ts/DAY_MS)`
  gives a pure, timezone-independent day number so streak/series math is
  deterministic in tests. An optional `tzOffsetMin` lets the UI bucket by the
  user's **local** day without making the logic locale-dependent.
- **Streak = reading + reviews both** (per the M3 scoping decision). A day is
  "active" if it has any exposure OR review event, so the streak reflects total
  engagement, not just graded study.
- **One grace day on the current streak.** It only breaks once a *whole* day is
  missed (last active day must be today or yesterday) — matches how
  Anki/Duolingo-style streaks feel, avoids punishing "haven't opened it yet
  today."
- **Distribution reuses `deriveStatus`** instead of re-implementing tiering, so
  the histogram and the glossing decision share the canonical
  `FAMILIARITY_TIERS` rule (D-014).
- **`activitySeries` is dense** (pre-filled empty days) so M3.2 can draw a
  fixed-width strip with no gap handling.
- **No "learned over time" series.** `level` is a *derived cache*, not a logged
  fact, so we can't truthfully reconstruct when a word crossed into "known".
  Left out rather than faked; revisit if we ever log level-crossings.
