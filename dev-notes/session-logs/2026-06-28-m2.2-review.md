# 2026-06-28 — M2.2: review queue + quiz UI

## Goal
Build the spaced-repetition review experience on top of the 2.1 SRS math:
query due words, show flashcards, grade them, and feed results back into the
schedule + event log.

## What shipped
- **Page:** `HTMLs/review.html`, `CSSs/review.css`, `JSs/review.js` (bundled →
  `dist/review.js`; added to `build.mjs`).
- **SRS:** `seedReview(…,{dueNow})`, `isReviewEligible`, `isUnscheduled`,
  `seedNewReviews` in `core/srs.js`.
- **Events:** `makeReviewEvent` (pure) + `appendReview`/`appendReviews`/
  `getReviewsForWord`/`countReviews` in `core/events.js` (IDB `reviews` store).
- **Constants:** `GRADE_QUALITY`, `REVIEW_SESSION_LIMIT`.
- **Popup:** Review button + due-count badge (`popup.html`/`.css`/`.js`).
- **Tests:** `tests/review.test.js` + extended `tests/srs.test.js`.
- Manifest → 1.0.4.

## Decisions
- **Review pages run on the extension origin**, so `review.js` talks to
  storage, IndexedDB, and the bundled dictionary **directly** — no background
  round-trip (that hop only exists for the content script's CORS-blocked BYOK
  fetch). Worth remembering: content-script IndexedDB writes live on the *page*
  origin, while the review page's review-event writes live on the *extension*
  origin. They don't share a DB. That's fine here — review reads the SRS state
  from the word bank (`chrome.storage.local`, shared everywhere) and only
  *writes* review events for its own history/analytics.
- **Newly-eligible words are seeded due *now*** (`seedNewReviews` →
  `seedReview(dueNow:true)`), not "tomorrow". A vocab learner opening Review
  should have something to do immediately; the Leitner ladder spaces things out
  from the first grade onward.
- **Eligibility** = tracked, not `known`/`ignored`, level < STOP_GLOSS_LEVEL.
  Onboarding-seeded "known" words (level 100) are correctly excluded.
- **Card backs filled on demand.** Read-tracked words usually have no stored
  gloss (glossing is live in the content script), so the back is looked up via
  `fetchTranslationFromLocalDictionary` and written back onto the record
  (enriches the bank; never clobbers an existing/BYOK meaning).
- **"Again" re-queues** the word within the same session (interval 0 → due now)
  rather than ending it; hard/good/easy finish the word for the session even if
  "hard" technically makes it due in <1 day.
- **Popup duplicates a little logic** (`countReviewDue`) because it's an
  unbundled classic script. Documented as a "keep in sync" mirror, same pattern
  the settings/popup already use for providers.

## Verification
- No npm in the authoring sandbox, and **esbuild's native binary is
  host-specific** so `node build.mjs` can't run here either (confirmed: it
  errors asking for the platform binary). Pure logic verified with plain Node:
  **61 SRS/review assertions pass**; import paths + exports for `review.js`
  checked by hand.
- **On your machine:** `npm run build` (now emits `dist/review.js` — five
  bundles total) then `npm test`. Load unpacked and click the popup's **Review**
  button to exercise the UI.
