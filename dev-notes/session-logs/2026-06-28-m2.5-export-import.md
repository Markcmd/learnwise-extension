# 2026-06-28 — M2.5: export / import

## Goal
Let users back up and restore their word bank, safely, across devices.

## What shipped
- **`core/exportImport.js`** (pure): `buildExport`, `extractBank`,
  `parseImport`, `mergeBank` (merge by `updatedAt`, newer wins).
- **Settings:** "Download" → **Export** (wrapped envelope); new **Import**
  button + file input that merges a backup into the live bank and reports
  `+added / updated / skipped`. Inlined mirror in `settingsWindow.js`.
- **Tests:** `tests/exportImport.test.js`. Manifest → 1.0.8.

## Decisions
- **Merge, don't replace.** Import merges into the existing bank by `updatedAt`
  (newer record wins). Restoring a backup never wipes fresher local progress,
  and syncing two devices via export/import converges sensibly. A full
  "replace" would be surprising and destructive.
- **Self-describing envelope, but tolerant import.** Export wraps the bank with
  a `format`/`version`/`exportedAt` header so future importers can branch on
  version; `extractBank` still accepts a legacy raw-bank dump so old downloads
  keep working.
- **Decks aren't serialized.** They're derived from frequency rank (2.4 pivot),
  so there's nothing to back up — one less thing to version.
- **Missing `updatedAt` = 0.** Defensive: a record without a timestamp loses to
  any timestamped one, and ties are skipped (keep local).
- **No schema migration on import.** Imported records may be an older shape, but
  `runMigration` already normalizes the whole bank on next load, so import stays
  simple. (If we ever import-then-use without a reload, revisit this.)

## Verification
- `core/exportImport.js` Node-verified: **24 assertions pass** (envelope,
  extract/parse incl. throw paths, merge precedence, key-normalize, no-mutation).
- `settingsWindow.js` + `core/exportImport.js` pass `node --check`.
- **On your machine:** `npm test`; then in Settings, Export a backup, change a
  word, Import the file back and confirm the status line + that newer local
  edits are preserved.
